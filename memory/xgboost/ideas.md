# Ideas — xgboost

- id: xgboost-binary-v1
  hypothesis: A binary XGBoost classifier trained on {1+2-star -> 0, 3+4+5-star -> 1}
    user-item pairs, ranked by predicted P(positive), beats the popularity
    baseline on precision@10 and recall@10 for recommendation.
  evidence: Explicit 3+4+5-star ratings are a strong positive signal and 1+2-star a
    strong negative; XGBoost exploits tabular user (age/gender/occupation) and
    item (genre/release-year) features without embedding training, so it is a
    cheap, interpretable proof of a pointwise ranking model.
  status: accepted

## Improvement ideas — pointwise XGBoost (ideation 2026-10-17)

Prioritized by expected gain vs popularity baseline. All target the root cause
(no collaborative/personalization signal) or a specific known weakness.

### Tier 1 — expected largest gain (inject collaborative signal)

- id: xgboost-latent-factors
  hypothesis: Feeding ALS or SVD latent-factor embeddings (user and item) as
    features into pointwise XGBoost beats the popularity baseline on
    precision@10/NDCG@10, because the GBM gains a collaborative signal it can
    cross with tabular features.
  approach: Train SVD/ALS offline on the full rating matrix; expose each user's
    and item's k-dim latent vector (k in 32..128) as numeric features, plus
    their dot product as a "predicted-rating proxy" feature. Keep existing
    tabular features.
  why: Directly supplies the missing user-item collaborative signal; the GBM
    learns non-linear interactions between latent affinity and item/user
    attributes instead of re-deriving popularity.
  metric: NDCG@10, precision@10, recall@10

- id: xgboost-rerank-collaborative-candidates
  hypothesis: Using pointwise XGBoost to re-rank a small candidate set
    generated by ALS/SVD (two-stage candidate generation + re-ranking) beats
    both the popularity baseline and raw pointwise GBM on precision@10/NDCG@10.
  approach: Generate top-N candidates per user from ALS/SVD, then score only
    those user-item pairs with XGBoost over rich features; return the re-ranked
    top-10.
  why: Fixes the fundamental problem — the GBM no longer ranks the entire
    catalog (where it just picks popular items) but discriminates among already
    relevant candidates; personalization comes from the candidate generator.
  metric: precision@10, NDCG@10, recall@10

### Tier 2 — strong expected gain (learned + engineered collaborative features)

- id: xgboost-cooccurrence-features
  hypothesis: Adding item-item co-occurrence (users who like A also like B) and
    user-genre affinity features beats the popularity baseline on NDCG@10 by
    encoding preference similarity directly.
  approach: Compute item co-occurrence counts / conditional probability from
    implicit ratings; for each candidate item, add features like max/sum
    co-occurrence with the user's top-rated items, plus user affinity per
    genre (normalized rating share).
  why: Gives the GBM explicit "this item is similar to what this user liked"
    and "this user likes this genre" signals, i.e. personalization beyond
    global popularity.
  metric: NDCG@10, precision@10

- id: xgboost-user-item-cross-terms
  hypothesis: Adding explicit user-item interaction features (e.g. user_mean *
    item_mean, user-genre affinity * item-genre indicator) beats the current
    additive tabular model on precision@10.
  approach: Engineer multiplicative cross terms between user statistics and
    item attributes so the GBM's trees can express "this user's taste meets
    this item" without requiring very deep trees to discover it.
  why: Current features enter mostly additively; cross terms make user-specific
    item preferences directly learnable, addressing the personalization gap.
  metric: precision@10, NDCG@10

### Tier 3 — moderate gain (label/optimization quality)

- id: xgboost-negative-sampling
  hypothesis: Training pointwise XGBoost on balanced positive/negative pairs via
    proper negative sampling (unseen/random negatives, not just 1-2 star) beats
    the current skewed-label framing on recall@10/hit-rate.
  approach: Sample negative user-item pairs from items the user has not rated
    (implicit negatives) at a controlled ratio, in addition to low ratings;
    train with balanced scale_pos_weight.
  why: The current class balance (up to 10:1) and "1-2 star = negative" framing
    drowns positive signal; explicit negatives better approximate "relevant vs
    irrelevant" ranking and lift recall.
  metric: recall@10, hit-rate@10

- id: xgboost-time-decay-popularity
  hypothesis: Replacing static item_rating_count with time-decayed recency-aware
    popularity/trend features beats the naive popularity baseline on NDCG@10.
  approach: Weight ratings by recency (exponential decay) to build item trend
    and user recent-taste features, so the model captures temporal preference
    drift the flat baseline misses.
  why: Fixes a specific weakness — the baseline is a static snapshot, while
    decayed popularity is personalized to "recent" behavior and item freshness.
  metric: NDCG@10, hit-rate@10

- id: xgboost-class-imbalance
  hypothesis: Cost-sensitive learning or SMOTE-style oversampling of the
    minority class improves ranking metrics vs the current single scale_pos_weight.
  approach: Use scale_pos_weight tuning, focal objective, or SMOTE on training
    positives to give rare positives more influence in the split/leaf objectives.
  why: Addresses the 5:1-10:1 class imbalance that biases the model toward the
    majority (popular) class and suppresses positive-item recall.
  metric: recall@10, precision@10

### Tier 4 — lower expected gain (tuning; no new signal)

- id: xgboost-hyperparameter-tuning
  hypothesis: Deeper trees + stronger regularization + early stopping improve
    precision@10/NDCG@10 modestly over the current max_depth=6/100-tree config.
  approach: Grid/random search over max_depth, min_child_weight, subsample,
    colsample_bytree, reg_lambda, learning_rate with early stopping and
    ranking-aware eval (NDCG@10).
  why: Only refines capacity/regularization; does not add collaborative signal,
    so expected gain is bounded and will not by itself close the baseline gap.
  metric: NDCG@10, precision@10

- id: xgboost-ranking-objective
  hypothesis: Switching from binary:logistic pointwise to a pairwise
    (rank:pairwise) or LambdaMART (rank:ndcg) objective improves NDCG@10 on the
    same features.
  approach: Re-train XGBoost with ranking objectives over per-user group data
    to optimize the ranking metric directly rather than pointwise likelihood.
  why: Aligns the training loss with the evaluation metric (NDCG), but shares
    the same feature limitation, so it is complementary to, not a substitute
    for, the collaborative-feature ideas above.
  metric: NDCG@10, precision@10
